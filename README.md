# 상권 Atlas Beta

한국·일본에서 음식점을 준비하는 사람을 위한 **모바일 우선 출점 검토 앱**입니다. PC에서는 지역·운영안 비교 화면을 넓게 사용할 수 있습니다.

**사이트:** https://tokyo-food-atlas-1024.lielikelife.chatgpt.site/

현재 단계는 소유자 전용 비공개 베타입니다. 지역 검색, 실제 한국 음식점 스냅샷, 지역별 공개 인구·직장 자료, 운영 조건에 따른 업종 후보, 매물 비용과 손익 계산, 계정별 기록 저장을 제공합니다. 일본 실시간 인구와 자동 상가 매물 공급은 계약 및 공식 연결 사양이 필요합니다. 운영 API 키가 없는 서비스를 연결 완료로 표시하지 않습니다.

한국 점포 원본은 **16개 시도 코드**를 사용하며 `12`를 `전남광주통합특별시`로 수록합니다. 과거 17개 시도나 광주/전남의 예전 코드를 하드코딩하지 않습니다. 검색 지역은 상권·행정동·시군구처럼 서로 다른 공간 단위를 포함하므로 5,479/7,230을 모두 같은 수준의 '동네 수'로 해석하지 않습니다.

자료가 없는 지역의 연령·유동인구는 만들어 채우지 않습니다. 전국 검색 지원과 전국 인구·실시간 지원은 별개입니다. 공식 자료의 구체적인 확보 범위, 해시, 라이선스, 예외는 [docs/DATA-COVERAGE.md](docs/DATA-COVERAGE.md), [docs/DATA-REPRODUCE.md](docs/DATA-REPRODUCE.md)와 `public/market/sources.json`에 있습니다.

## 사용할 수 있는 흐름

1. 한국·일본을 선택하고 지역명으로 검색합니다. 서버 결과는 한 번에 20개로 제한되며 시도·도도부현으로 좁힐 수 있습니다.
2. 조달 가능한 총 창업 예산과 운영 시간·경험·운영 형태를 입력합니다.
3. 조건을 만족하는 최대 3개 업종 운영안을 비교합니다. 조건 밖 후보로 세 개를 억지로 채우지 않습니다.
4. 거주·생활·직장 자료의 연령 구성을 확인하고, 한국에서는 대표점 주변 음식점을 반경·업종·상호로 조회합니다.
5. 공개 참고 매물 또는 직접 확인한 매물을 등록해 임대료·관리비·보증금 등 실제 비용을 적용합니다.
6. 객단가, 좌석·회전 또는 주문 건수, 인건비, 원가율, 초기 현금, 대출 원금 등을 조정하고 손익분기와 현금흐름을 봅니다.
7. 운영안·경쟁점 조사·현장 체크를 저장합니다. 같은 계정의 기기 간 동기화, 오프라인 대기, 충돌 선택, 기록 내보내기를 지원합니다.

### 결과 해석

- 업종 점수는 명시한 운영 조건과 공개 지역 신호에 따른 **규칙 기반 검토 순위**입니다. 실제 매출 예측, 성공확률 또는 검증된 추천 모델이 아닙니다.
- 지역 연령은 개별 가게의 고객 연령이 아닙니다. 점포별 고객 연령은 `null`이며 외모·리뷰 작성자·주변 연령으로 추정하지 않습니다.
- 월세·공사비·객단가 등 기본값은 편집 가능한 운영 가정입니다. 실제 시세·견적·매출로 표시하지 않습니다.
- 한국·일본 수치를 같은 연도·같은 조사 정의의 통계처럼 직접 합산하지 않습니다. 통화도 원화/엔화를 분리합니다.
- 분기 점포 집계는 현재 영업 점포 전수조사가 아닙니다. 폐업수를 빼서 영업수를 만들지 않습니다. 원자료 예외 100행에는 검토 표시가 있습니다.
- 지도 대표점은 상권의 경계나 점포 출입구가 아닙니다. 전국 행정동의 점포 좌표 평균과 일본 행정기관 청사 대표점은 해당 정밀도를 표시합니다.

## 앱 구조

- Vinext / React 19 / Vite / Cloudflare Workers
- `app/atlas-app.tsx`: 기존 검증된 DOM 화면을 모바일 웹앱으로 로드하는 클라이언트 브리지
- `public/app.js`, `public/beta-ui.js`: 화면·지역 검색·연결 설정·매물 입력
- `public/domain.js`: 재무 계산; `public/recommend.js`: 조건별 업종 검토
- `public/cloud-sync.js`: 계정별 기기 저장·전송 대기열·충돌 처리
- `lib/atlas-server.mjs`: 인증·D1 저장·암호화 키·API·MCP·자료 릴리스
- `lib/market-data.mjs`: 지역 및 반경 음식점 조회, 릴리스 일관성
- `lib/provider-connectors.mjs`: 고정 공식 호스트만 호출하는 공급자 어댑터
- D1 `DB`: 계정 기록, 암호화 키, 캐시, 작업 내역, 데이터 릴리스 목록
- R2 `BUCKET`: 버전별 공개 자료 묶음; 최초에는 번들 정적 자료 사용
- `public/market/manifest.json`: 442개 JSON 파일의 목록 및 SHA-256, 단일 파일 6MiB 미만

442개 원천 정규화 파일을 초기 화면에서 모두 다운로드하지 않습니다. 지역 검색 인덱스와 필요한 상세 자료만 읽습니다. 한국 점포 조회는 bounding box로 시군구 청크를 고른 뒤 순차 처리합니다. 시군구 경계를 넘는 반경 검색을 지원하며 최대 8청크로 제한될 때 부분 조회임을 응답합니다. 실제 공급 계약이 없는 공개 Overpass 서버를 음식점 수집 경로로 사용하지 않습니다.

## 개발과 검증

프로젝트에 포함된 공식 도구 환경과 잠금 파일을 사용합니다.

```bash
npm run install:ci
npm run build
npm run db:generate
node tests/finance.cjs
node tests/recommend.cjs
node tests/cloud-sync.test.mjs
node tests/provider.test.mjs
node tests/server.test.mjs
node tests/market-data.test.mjs
node tests/frontend-validation.cjs
node tests/source-refresh.cjs
```

관리형 개발 환경에서는 `sites-preview start <절대 프로젝트 경로>`를 사용합니다. 별도의 미리보기 서버를 띄우지 않습니다. 미리보기의 인증 모의 기능은 비활성입니다. 인증된 기록 API는 미리보기에서도 실제 인증 헤더가 없으면 401을 반환합니다. 계정 격리·CAS·암호화 검증은 SQLite 기반 D1 테스트 하네스로 재현합니다.

D1 스키마는 `db/schema.ts`, 생성된 마이그레이션은 `drizzle/`에 있습니다. 테이블 생성은 배포 마이그레이션으로만 수행하며 요청 처리에서 생성하지 않습니다. 로컬 마이그레이션은 한 번만 적용합니다.

```bash
node --import ./scripts/sites-env.mjs ./node_modules/wrangler/bin/wrangler.js d1 execute DB --local --config dist/server/wrangler.json --persist-to .wrangler/state --file drizzle/0000_chief_leader.sql
```

`prepare-data.py`는 최초 MVP 자료 재현용입니다. 현재 앱 자료를 덮지 않도록 `work/legacy-snapshot/`에 출력합니다. 베타 패키지는 `scripts/build-market-data.py`와 DATA-REPRODUCE 문서의 원본 입력을 사용합니다.

### 중요한 검증 범위

재무 항등식·예산 제외·낮은 예산 후보 없음·누락 자료, 오프라인 큐·계정 전환·다중 탭·동시 수정·삭제 tombstone·기기 저장 실패, 계정별 SQL 분리·암호화·교차 출처 쓰기 거절·원자적 자료 활성화, 실제 한국 여러 도시와 시군구 경계 반경 검색을 검증합니다. 공급자 fixture 테스트는 실제 확보한 무키 서울 sample과 합성 POI 응답을 재생하는 테스트이며, 미발급 운영 키의 실제 연결 성공을 증명하지 않습니다.

## 계정과 API 키

운영에서는 Sites가 전달하는 `oai-authenticated-user-id`를 사용합니다. 브라우저가 보낸 `X-Atlas-User-Id`는 계정 전환 경합 확인용일 뿐 인증 수단이 아닙니다. 모든 개인 기록 SQL에 소유자 조건을 적용합니다. 활성 항목은 1,000개, 삭제 버전을 포함한 전체 키는 5,000개까지 보존합니다. 삭제 버전을 임의로 지워 오래된 기기의 기록이 복구되는 일을 막습니다. 같은 키의 수정은 `expectedVersion`에 기반한 CAS로 처리하고 삭제 버전을 보존합니다.

키는 AES-256-GCM으로 암호화합니다. 각 저장마다 임의 IV, 계정+공급자 AAD를 사용합니다. 암호화 마스터키는 서버 환경 변수에만 있으며, 키 조회 API는 plaintext를 반환하지 않습니다. 연결 상태는 키 존재와 실제 응답 검증을 구분합니다. 운영 환경 변수, API 키, 서비스 토큰은 코드·버전 관리·브라우저 저장소에 넣지 않습니다.

필수 운영 환경 변수:

| 이름 | 용도 |
|---|---|
| `ATLAS_ENCRYPTION_KEY` | 안전하게 생성한 32바이트 키의 base64; 교체 시 기존 공급자 키 재암호화 필요 |
| `ATLAS_OWNER_EMAIL` | Sites에서 검증된 소유자 이메일, 관리 갱신 작업에만 사용 |
| `ATLAS_IMPORT_SECRET` | 소유자 자료 릴리스 업로더 인증; Sites 접근 토큰과 함께 사용 |

공급자 운영 키는 앱의 **연결 설정**에서 입력할 수 있습니다. 서울 공식 원천의 HTTP 키 전송, 카카오 표시·캐시 조건, Hot Pepper의 사업모델 이용 제한은 각각 명시 확인이 필요합니다. 권한 확인을 생략한 키만으로 호출을 허용하지 않습니다. 도코모 인구와 상가 매물 피드는 계약·응답 스키마 전에는 비활성입니다. 자세한 내용은 [docs/CONNECTORS.md](docs/CONNECTORS.md)를 참조하세요.

## 데이터 갱신

- 앱을 보고 있을 때 서울 지정 장소 인구 패널은 5분 간격으로 조회합니다. 서버 캐시도 5분입니다. 원천 시각이 오래됐거나 오류·대체자료이면 실시간 정상값으로 표시하지 않습니다.
- `POST /api/refresh` 및 MCP `atlas_refresh_sources`는 사이트 소유자의 실제 인구 조회·캐시·작업 기록을 수행합니다.
- 전국 점포/서울 분기/도쿄 센서스 스냅샷은 별도 자료 릴리스입니다. 실시간 인구 조회로 이 자료들의 기준일을 변경하지 않습니다.
- 데이터 릴리스는 업로드 → 전체 파일 수/해시/크기 대조 → D1 활성 포인터 원자적 변경 순서입니다. 활성 R2 파일이 없으면 503을 반환하며 과거 번들 파일과 섞지 않습니다.

```bash
python scripts/import-market.py
```

위 업로더는 검증된 Atlas 사이트 주소에만 접속하며, 서비스 토큰과 import secret은 **숨겨진 표준입력 JSON**으로 받습니다. 인자·로그·설정 파일에 넣지 않습니다. 전달 항목은 `siteUrl`, `siteToken`, `importSecret`, 선택적인 `version`입니다. 각 공개 파일 해시를 로컬에서 확인한 뒤 제한된 동시성으로 업로드하고 활성 버전을 재조회합니다. 실패한 staging 묶음은 활성화되지 않습니다.

MCP는 `/mcp`에서 `atlas_status`, `atlas_search_regions`, `atlas_lookup_shops`, `atlas_refresh_sources`, `atlas_export_my_records`를 제공합니다. 읽기 권한과 소유자 전용 갱신 권한을 구분합니다. 스케줄은 실제 배포된 도구의 갱신·읽기 검증 후 설정하며, 연결 확인 전에는 무인 갱신이 동작한다고 표시하지 않습니다.

## 상용 전 남은 조건

1. 서울 운영 키·한국 장소 API·일본 음식점 API의 실제 키와 서비스 이용 범위 확인
2. 일본/한국 전국 실시간 유동인구 공급, 상가 매물 표시·갱신·삭제 계약
3. 지역별 실제 고객 연령을 제공할 수 있는 합법적인 결제/패널 자료의 수급 검토; 없으면 계속 미확인
4. 베타 이용자 수를 늘리기 전 부하·공급자 쿼터·가용성·장애 알림·백업 복구 검증
5. 공개 서비스의 개인정보/이용조건, 요금·환불 정책이 필요한 사업모델 확정
6. 추천 규칙을 실제 출점·운영 성과로 평가하는 검증 자료

이 저장소는 위 외부 조건을 완료했다고 주장하지 않습니다. 소유자 전용 베타의 실사용 기능과 운영 연결 지점을 제공하고, 미확보 자료를 명시합니다.
